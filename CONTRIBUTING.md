# Contributing

Thanks for helping the garden grow. The short version: **every number has a source, new notes start as seedlings, and people verify what agents draft.**

## Workflow

1. Pick or open a GitHub Issue so others know what you're working on.
2. Make a branch (or use GitHub's web editor, which makes one for you).
3. Edit or add notes in `content/`. Start new notes from `content/templates/note-template.md`.
4. Open a pull request and fill in the checklist.
5. One other person reviews. The site redeploys automatically after merge.

## Note maturity

| Stage | Means | Who can set it |
| --- | --- | --- |
| 🌱 `seedling` | Drafted; sources not yet checked | Anyone, including agents |
| 🌿 `budding` | A person opened every source and checked the claims | A person, who adds their name to `verified_by` |
| 🌳 `evergreen` | Stable, well sourced, reviewed by the branch owner | The branch owner |

## Writing style

- Plain language first; define jargon the first time.
- One idea per note; link generously with `[[wikilinks]]`.
- Numbers: value, unit, year, region, source.
- Where sources disagree, show both under **Open questions**.
